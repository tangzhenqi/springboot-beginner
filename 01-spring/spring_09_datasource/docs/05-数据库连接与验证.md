## 9. 数据库连接何时建立

这是本案例最容易混淆的地方。

### 9.1 四个不同阶段

1. **加载 JDBC 驱动**：JVM 能找到 MySQL 驱动类；
2. **创建 DataSource**：Spring 调用构造器创建连接池对象；
3. **初始化连接池**：连接池准备内部结构，可能按配置预建物理连接；
4. **借用连接**：应用调用 `getConnection()`，连接池返回可用的 `Connection`。

不同连接池可以在第 3 阶段采取不同策略：有的默认懒加载，有的默认预建若干连接，有的还会因为状态查询或 `toString()` 而触发初始化。

### 9.2 常见连接失败

| 问题 | 常见现象 |
| --- | --- |
| 数据库不存在 | `Unknown database 'xxx'` |
| MySQL 未启动或端口不通 | `Communications link failure`、`Connection refused` |
| 用户名或密码错误 | `Access denied for user ...` |
| JDBC URL 参数不合适 | SSL、时区或字符集警告/异常 |
| 驱动版本与类名不匹配 | `ClassNotFoundException` 或驱动加载失败 |

若直接调用 `DataSource.getConnection()`，通常首先得到 `SQLException`。如果通过 Spring JDBC 的 `JdbcTemplate`、`DataSourceUtils` 等组件访问，Spring 可能进一步把底层异常转换为自己的数据访问异常，例如 `CannotGetJdbcConnectionException`。

## 10. 如何真正验证数据库连接

当前 `App` 只观察数据源对象。若要明确验证数据库是否可连接，可以临时加入如下代码：

```java
import java.sql.Connection;
import java.sql.ResultSet;
import java.sql.Statement;

try (Connection connection = dataSource_druid.getConnection();
     Statement statement = connection.createStatement();
     ResultSet resultSet = statement.executeQuery("SELECT 1")) {

    if (resultSet.next()) {
        System.out.println("数据库连接成功，结果：" + resultSet.getInt(1));
    }
}
```

`try-with-resources` 会自动关闭 `ResultSet`、`Statement` 和 `Connection`。对于池化连接，关闭 `Connection` 通常代表归还连接，而不是断开底层物理连接。

运行前需要满足：

1. 本机 MySQL 监听相应端口；
2. 已创建 `spring_db` 数据库；
3. 用户名和密码与配置一致；
4. 该用户有访问 `spring_db` 的权限。

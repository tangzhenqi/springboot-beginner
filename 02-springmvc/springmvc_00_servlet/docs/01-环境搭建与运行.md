# 01 环境搭建与运行

## 一、依赖说明

本模块 `pom.xml` 只引入了两个依赖，刻意保持最小化，避免框架干扰对 Servlet 本身的理解。

```xml
<dependency>
  <groupId>javax.servlet</groupId>
  <artifactId>javax.servlet-api</artifactId>
  <version>3.1.0</version>
  <scope>provided</scope>
</dependency>
<dependency>
  <groupId>javax.servlet</groupId>
  <artifactId>jstl</artifactId>
  <version>1.2</version>
</dependency>
```

### 1. 为什么 servlet-api 的 scope 必须是 provided

`javax.servlet-api` 里只有**接口和抽象类**（`Servlet`、`HttpServlet`、`HttpServletRequest`…），没有实现。
真正的实现类在 Tomcat 的 `lib/servlet-api.jar` 里，Tomcat 启动时会加载。

Maven 的依赖范围：

| scope | 编译期 | 测试期 | 运行期 | 是否打进 war 包 |
| --- | :---: | :---: | :---: | :---: |
| compile（默认） | ✅ | ✅ | ✅ | ✅ |
| **provided** | ✅ | ✅ | ❌ | ❌ |
| runtime | ❌ | ✅ | ✅ | ✅ |
| test | ❌ | ✅ | ❌ | ❌ |

如果写成默认的 `compile`，war 包的 `WEB-INF/lib` 下会多出一份 `servlet-api.jar`，
和 Tomcat 自带的那份冲突，启动时典型报错：

```
java.lang.ClassCastException / ClassNotFoundException: javax.servlet.Servlet
Offending class: javax/servlet/Servlet.class
```

**结论：servlet-api、jsp-api 这类"容器已经提供"的依赖，一律用 provided。**

### 2. 为什么没有引入 jsp-api

JSP 文件不是在编译期处理的，而是 Tomcat 在运行时把 `.jsp` 翻译成 `.java` 再编译（见 `10-JSP与EL、JSTL.md`），
这个过程用的是 Tomcat 自己的 Jasper 引擎和 jsp-api。本模块的 Java 代码里没有直接引用 `javax.servlet.jsp.*` 的类，
所以不需要这个依赖。

如果你要在 Java 代码里写自定义标签（继承 `SimpleTagSupport`），才需要补上：

```xml
<dependency>
  <groupId>javax.servlet.jsp</groupId>
  <artifactId>javax.servlet.jsp-api</artifactId>
  <version>2.3.1</version>
  <scope>provided</scope>
</dependency>
```

### 3. jstl 为什么不是 provided

Tomcat **不提供** JSTL 实现（Tomcat 只实现了 Servlet/JSP 规范，JSTL 是独立的标签库规范），
所以 `jstl-1.2.jar` 必须打进 war 包的 `WEB-INF/lib`，用默认的 compile 范围。

> `javax.servlet:jstl:1.2` 这一个 jar 同时包含了 JSTL 的 API 和 Apache 的实现，
> 用它就够了；老教程里的 `jstl.jar` + `standard.jar` 是 JSTL 1.1 的分包方式。

## 二、打包插件

```xml
<plugin>
  <groupId>org.apache.tomcat.maven</groupId>
  <artifactId>tomcat7-maven-plugin</artifactId>
  <version>2.1</version>
  <configuration>
    <port>80</port>
    <path>/</path>
    <uriEncoding>UTF-8</uriEncoding>
  </configuration>
</plugin>
```

| 配置项 | 含义 | 影响 |
| --- | --- | --- |
| `port` | 内置 Tomcat 的端口 | 80 端口可省略不写，访问 `http://localhost/` |
| `path` | 项目虚拟目录（context path） | 配 `/` 时 `request.getContextPath()` 返回空串；配 `/demo` 则所有地址都要加 `/demo` 前缀 |
| `uriEncoding` | url 的解码字符集 | **解决 GET 请求中文乱码**，详见 `04-Request请求对象详解.md` |

`<packaging>war</packaging>` 也不能少 —— Web 项目打的是 war 包，不是 jar 包。

## 三、运行方式

### 方式一：Maven 内置 Tomcat（推荐，无需装 Tomcat）

```bash
# 在 02-springmvc 目录下执行
mvn -pl springmvc_00_servlet tomcat7:run
```

看到下面的输出说明启动成功：

```
==================================================
【Listener】应用启动完成：Servlet详细案例
【Listener】服务器信息：Apache Tomcat/7.0.47
...
==================================================
【1-实例化】LifeCycleServlet 构造方法执行，对象地址：...
【2-初始化】init方法执行，servlet名称：LifeCycleServlet
[INFO] Running war on http://localhost:80/
```

浏览器访问 <http://localhost/>。停止服务：控制台按 `Ctrl + C`（这样才会触发 `destroy()`）。

### 方式二：IDEA 配置本地 Tomcat

1. 先在本机安装 Tomcat 8/9（Servlet 3.1 需要 Tomcat 8+，Tomcat 7 只支持到 Servlet 3.0，本案例的 API 都在 3.0 范围内，两者都能跑）
2. `Run` → `Edit Configurations` → `+` → `Tomcat Server` → `Local`
3. `Deployment` 标签页 → `+` → `Artifact` → 选择 `springmvc_00_servlet:war exploded`
4. `Application context` 填 `/`
5. `Server` 标签页把 `On 'Update' action` 设为 `Update classes and resources`，改 JSP 不用重启

### 方式三：只编译验证，不启动

```bash
mvn -pl springmvc_00_servlet clean compile
```

## 四、war 包目录结构

理解这个结构，才能理解为什么资源要放在特定的位置。

开发时的 `src/main/webapp` 目录，打包后就是 war 包的根目录：

```
springmvc_00_servlet.war
├── index.jsp                 ← 浏览器可直接访问 http://localhost/index.jsp
├── css/common.css            ← 浏览器可直接访问 http://localhost/css/common.css
└── WEB-INF/                  ← 受保护目录，浏览器无法直接访问
    ├── web.xml               ← 部署描述符
    ├── classes/              ← src/main/java 编译后的 .class 和 src/main/resources 的配置文件
    │   └── com/springmvc/...
    ├── lib/                  ← 所有 compile/runtime 范围的依赖 jar
    │   └── jstl-1.2.jar
    └── pages/                ← 本案例的 JSP 视图
        ├── login.jsp
        └── list.jsp
```

**关键点：`WEB-INF` 是 Servlet 规范规定的受保护目录**，浏览器直接输入
`http://localhost/WEB-INF/pages/list.jsp` 会得到 404，只有服务器内部的**转发**才能访问到它。
所以本案例把所有 JSP 视图都放在 `WEB-INF/pages` 下，强制用户必须经过 Servlet 才能看到页面，
避免绕过登录校验、绕过数据查询直接访问页面（那样页面上什么数据都没有）。

## 五、常见启动问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Address already in use: bind` | 80 端口被占用（常见于 Nginx、其他 Tomcat） | 改 `pom.xml` 的 `<port>8080</port>`，访问 `http://localhost:8080/` |
| 访问首页 404 | `<path>` 配的不是 `/` | 访问地址要带上虚拟目录 |
| 页面中文乱码 | 见 `13-常见问题FAQ.md` | |
| 改了 Java 代码不生效 | Tomcat 未热部署 | 重启服务；`tomcat7:run` 需要重新执行 |
| `Cannot access ... in offline mode` | Maven 离线模式且本地仓库无该插件 | 去掉 `-o` 参数联网构建一次 |

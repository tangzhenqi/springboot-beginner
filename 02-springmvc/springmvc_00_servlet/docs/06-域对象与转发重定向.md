# 06 域对象与转发重定向

对应代码：`RequestDemoServlet`、`UserServlet`、`AppContextListener`、所有 JSP 页面

## 一、什么是域对象

**域对象 = 能存取数据、且数据在特定范围内共享的对象。**

Web 开发中经常需要「A 组件产生的数据，让 B 组件用」。域对象就是它们之间的**共享区域**，
不同域对象的区别只在于**数据能活多久、能被谁看到**。

所有域对象都有同样的四个方法：

```java
void   setAttribute(String name, Object value);   // 存
Object getAttribute(String name);                 // 取，不存在返回null
void   removeAttribute(String name);              // 删
Enumeration<String> getAttributeNames();          // 所有key
```

## 二、四大域对象对比

| 域对象 | 类型 | 作用范围 | 创建时机 | 销毁时机 | JSP 中的名字 |
| --- | --- | --- | --- | --- | --- |
| `pageContext` | `PageContext` | **当前 JSP 页面内** | 页面开始渲染 | 页面渲染结束 | `pageScope` |
| `request` | `HttpServletRequest` | **一次请求（含转发）** | 请求到达 | 响应结束 | `requestScope` |
| `session` | `HttpSession` | **一次会话（一个浏览器）** | 首次 `getSession()` | 超时/`invalidate()`/服务器关闭 | `sessionScope` |
| `servletContext` | `ServletContext` | **整个应用（所有用户）** | 应用启动 | 应用关闭 | `applicationScope` |

**范围从小到大：page < request < session < application**

```
┌─ ServletContext（应用级，所有人共享，服务器关才没）────────────────┐
│                                                                  │
│  ┌─ session（张三的会话）──────┐  ┌─ session（李四的会话）─────┐  │
│  │                            │  │                           │  │
│  │  ┌─ request（一次请求）─┐   │  │  ┌─ request ─┐            │  │
│  │  │  ┌─ pageContext ─┐  │   │  │  │           │            │  │
│  │  │  └───────────────┘  │   │  │  └───────────┘            │  │
│  │  └────────────────────┘   │  │                           │  │
│  └────────────────────────────┘  └───────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

## 三、选哪个域？—— 最小够用原则

**能用小的绝不用大的。** 范围越大，占用内存越久，越容易出现数据串台和内存泄漏。

| 需求 | 选择 | 本案例中的例子 |
| --- | --- | --- |
| Servlet 查的数据传给 JSP 展示 | **request** | `UserServlet.list()` 存 `userList` |
| 表单校验失败的错误提示 | **request** | `login()` 存 `errorMsg`，转发回登录页 |
| 记录当前登录用户 | **session** | `login()` 存 `loginUser` |
| 购物车、验证码 | session | — |
| 全站公告、在线人数、字典数据 | **application** | `AppContextListener` 存 `appName`、`onlineCount` |
| JSP 页面内的临时变量 | pageContext | — |

### ⚠️ 用错域的典型后果

```java
// ❌ 把查询结果放session：用户A看到用户B的数据 / 数据不刷新 / 内存暴涨
session.setAttribute("userList", userService.findAll());

// ❌ 把登录用户放request：转发能拿到，但下一次请求就没了，等于没登录
request.setAttribute("loginUser", user);

// ❌ 把用户信息放application：所有人共用一个"当前用户"，登录就串号了
context.setAttribute("loginUser", user);
```

## 四、案例中的域对象实战

### 1. request 域：Servlet → JSP 传数据

```java
// UserServlet.list()
public String list(HttpServletRequest request, HttpServletResponse response) {
    List<User> userList = userService.findAll();
    request.setAttribute("userList", userList);     // ① 存入request域
    return "/WEB-INF/pages/list.jsp";               // ② 转发（BaseServlet执行）
}
```

```jsp
<%-- list.jsp --%>
<c:forEach items="${userList}" var="user">          <%-- ③ EL从域中取出 --%>
    <td>${user.username}</td>
</c:forEach>
```

**注意第 ② 步必须是转发**。如果改成重定向，就是两次请求，第二次请求的 request 是新对象，
`${userList}` 什么都取不到，页面一片空白。

### 2. session 域：跨请求保存登录状态

```java
// UserServlet.login() —— 登录成功时存
HttpSession session = request.getSession();
session.setAttribute(SESSION_USER, user);
```

```java
// LoginCheckFilter —— 后续每次请求校验
HttpSession session = request.getSession(false);
if (session != null && session.getAttribute(UserServlet.SESSION_USER) != null) {
    chain.doFilter(request, response);      // 已登录，放行
}
```

```jsp
<%-- list.jsp —— 页面上显示当前用户 --%>
当前登录用户：<b>${sessionScope.loginUser.username}</b>
```

### 3. application 域：全应用共享

```java
// AppContextListener.contextInitialized() —— 应用启动时存
ServletContext context = sce.getServletContext();
context.setAttribute("appName", "Servlet详细案例");
```

```jsp
<%-- index.jsp —— 任何页面都能取 --%>
应用名称：${applicationScope.appName}　|　当前在线：${applicationScope.onlineCount}
```

## 五、转发 forward

```java
request.getRequestDispatcher("/WEB-INF/pages/list.jsp").forward(request, response);
```

### 执行过程

```
浏览器                 服务器
  │                    ┌──────────────────────────────┐
  ├──① 请求 /user/list─→│ UserServlet.list()           │
  │                    │   查数据 → 存request域         │
  │                    │   ↓ forward（服务器内部跳转）  │
  │                    │ list.jsp                     │
  │                    │   读request域 → 渲染html      │
  │←──② 响应 html ──────┤                              │
  │                    └──────────────────────────────┘
      整个过程只有一次请求，request/response对象自始至终是同一对
```

### 特点

- 地址栏**不变**（还是 `/user/list`）
- **一次**请求，request 域数据**共享**
- **只能**跳转本项目内的资源（因为是服务器内部行为）
- **可以**访问 `WEB-INF` 下的资源
- 路径**不带**虚拟目录

### ⚠️ 转发之后不要再写数据

```java
// ❌ 报错：IllegalStateException: Cannot forward after response has been committed
response.getWriter().write("已经写了内容");
request.getRequestDispatcher("/a.jsp").forward(request, response);

// ❌ 转发之后的代码仍会执行（forward不是return！）
request.getRequestDispatcher("/a.jsp").forward(request, response);
response.getWriter().write("这行会抛异常");

// ✅ 转发后立即return
request.getRequestDispatcher("/a.jsp").forward(request, response);
return;
```

## 六、重定向 redirect

```java
response.sendRedirect(request.getContextPath() + "/user/list");
```

### 执行过程

```
浏览器                                          服务器
  ├──① 请求 /user/save (POST) ──────────────────→ UserServlet.save()
  │                                                保存数据
  │←─② 响应 302 + Location:/user/list ───────────┤
  │
  ├──③ 浏览器自动重新请求 /user/list (GET) ───────→ UserServlet.list()
  │←─④ 响应 列表页html ──────────────────────────┤
      两次独立的请求，两对request/response对象
```

### 特点

- 地址栏**改变**（变成 `/user/list`）
- **两次**请求，request 域数据**丢失**
- **可以**跳转到任意地址，包括外部站点（`sendRedirect("https://www.baidu.com")`）
- **不能**访问 `WEB-INF` 下的资源（浏览器发起的请求会被容器拦截）
- 路径**必须带**虚拟目录

## 七、完整对比表（背下来）

| 对比项 | 转发 forward | 重定向 redirect |
| --- | --- | --- |
| API | `request.getRequestDispatcher(path).forward(req,resp)` | `response.sendRedirect(path)` |
| 请求次数 | **1 次** | **2 次** |
| 地址栏 | 不变 | 改变 |
| 谁发起的跳转 | 服务器内部 | 浏览器 |
| 状态码 | 200 | 302 |
| 能否跳外部站点 | ❌ 只能本项目 | ✅ 可以 |
| request 域数据 | ✅ 共享 | ❌ 丢失 |
| 能否访问 WEB-INF | ✅ 可以 | ❌ 不可以 |
| 路径带虚拟目录 | ❌ 不带 | ✅ 必须带 |
| 效率 | 略高（1 次请求） | 略低（2 次请求） |
| 表单重复提交风险 | 有 | 无 |

## 八、什么时候用哪个？

### 用转发的场景

**需要把数据带到下一个资源展示的时候。**

```java
// 查询列表 → 转发到列表页
request.setAttribute("userList", list);
return "/WEB-INF/pages/list.jsp";

// 校验失败 → 带着错误提示转发回表单页（还能回显用户填过的内容）
request.setAttribute("errorMsg", "用户名或密码错误");
request.setAttribute("username", username);
return "/WEB-INF/pages/login.jsp";
```

### 用重定向的场景

**"写操作"成功之后，跳去一个"读操作"页面（PRG 模式）。**

```java
// 新增/修改/删除/登录 成功后
return "redirect:/user/list";
```

原因见 `05-Response响应对象详解.md` 的「防止表单重复提交」。

### 本案例的选择一览

| 方法 | 结果 | 跳转方式 | 原因 |
| --- | --- | --- | --- |
| `toLogin` | — | 转发 | 要把 cookie 里的用户名带给页面回显 |
| `login` | 失败 | 转发 | 要把 errorMsg 带回登录页 |
| `login` | 成功 | **重定向** | 防止刷新重复提交登录表单 |
| `list` | — | 转发 | 要把 userList 带给列表页 |
| `save` | 失败 | 转发 | 要把 errorMsg 和已填数据带回表单 |
| `save` | 成功 | **重定向** | 防止刷新重复新增 |
| `delete` | 成功 | **重定向** | 防止刷新重复删除 |
| `logout` | — | **重定向** | session 已销毁，没有数据要传 |

## 九、路径问题总结（易错）

**判断标准：这个路径最终是给"浏览器"用的，还是给"服务器"用的？**

| 路径出现的位置 | 谁来解析 | 是否要加虚拟目录 |
| --- | --- | --- |
| `response.sendRedirect(path)` | 浏览器 | ✅ 要 |
| `request.getRequestDispatcher(path)` | 服务器 | ❌ 不要 |
| JSP/HTML 里的 `<a href>`、`<form action>`、`<img src>`、`<link href>` | 浏览器 | ✅ 要 |
| `cookie.setPath(path)` | 浏览器 | ✅ 要 |
| `getServletContext().getRealPath(path)` | 服务器 | ❌ 不要 |

### 页面中的标准写法

```jsp
<a href="${pageContext.request.contextPath}/user/list">用户列表</a>
<form action="${pageContext.request.contextPath}/user/save" method="post">
<link rel="stylesheet" href="${pageContext.request.contextPath}/css/common.css">
```

`${pageContext.request.contextPath}` 就是 `request.getContextPath()` 的 EL 写法。
本案例所有页面都这样写，所以把 `<path>` 从 `/` 改成 `/demo` 也不会有任何链接失效。

### 相对路径为什么危险

```jsp
<%-- ❌ 相对路径：相对于"当前浏览器地址栏的地址"，而不是文件所在位置 --%>
<a href="user/list">用户列表</a>
```

在 `/index.jsp` 点它会访问 `/user/list`（正确）；
但在 `/user/toAdd` 页面点它会访问 `/user/user/list`（404）。
**Web 开发中一律用「虚拟目录 + 绝对路径」，不要用相对路径。**
